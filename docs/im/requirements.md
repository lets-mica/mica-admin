# IM 模块需求文档

> 基于 [README.md](./README.md) 中定义的范围,**Phase 0 / Phase 1 / Phase 1.1** 的完整需求。

## 角色与场景

| 角色 | 描述 | 典型使用场景 |
|---|---|---|
| **普通员工** | mica-admin 注册用户 | 找人聊天、加入部门群、接收系统通知 |
| **管理员** | 拥有 `im:admin` 权限 | 查看 IM 总览、踢人、群管理 |
| **系统** | mica-admin 后台任务 | 发送系统通知(订单/审批/告警) |

## Phase 0 — 消息推送通道

> **目标**:把 mica-admin 的系统消息(`sys_message` 推送)从 HTTP 轮询升级为 MQTT 推送。
> 这是 mica-mqtt 接入的最小验证,为后续 IM 打基础。

### 用户故事

#### US-0-1 系统通知实时触达

> **作为** 普通员工
> **我想要** 在浏览器/App 后台时也能立即收到系统通知
> **以便** 不漏掉审批、订单变更等关键消息

**验收**:

- 管理员在 Web 后台发布一条 `sys_message`
- 用户在前台登录的浏览器/App 在 **< 5 秒** 内收到推送
- 离线用户下次上线时,优先拉取离线期间的消息

#### US-0-2 在线状态可见

> **作为** 普通员工
> **我想要** 看到其他同事是否在线
> **以便** 知道什么时候发消息对方能立刻看到

**验收**:

- 用户登录后,Web/App 显示该用户"在线"
- 用户退出登录或断网 30 秒后,显示"离线"

### 功能需求

| ID | 功能 | 优先级 |
|---|---|---|
| F0-1 | mica-mqtt-server 集成到 mica-admin-server | P0 |
| F0-2 | JWT 鉴权:CONNECT 包 username=token,服务端校验 | P0 |
| F0-3 | 用户上线时 PUBLISH `im/status/{userId}/state=online`(retained) | P0 |
| F0-4 | 用户下线(LWT)时 retained 自动更新为 offline | P0 |
| F0-5 | `SysMessageServiceImpl.publish()` 增加 MQTT 推送(per-user topic) | P0 |
| F0-6 | Web 端集成 mqtt.js,订阅 `im/sys/{userId}/system` | P0 |
| F0-7 | App 端原生 MQTT 客户端订阅同上 | P0 |
| F0-8 | MQTT broker 配置端口 1883(TCP) + 9001(WebSocket) | P0 |
| F0-9 | 鉴权失败时 broker 拒绝连接,错误码 5(Not Authorized) | P0 |
| F0-10 | 离线消息:用户上线时拉取 `sys_user_message` 中未读消息 | P0 |

### 非功能需求

| 类别 | 要求 |
|---|---|
| 消息延迟 | 单机部署 < 1s,10 用户并发压测 < 2s |
| 可靠性 | QoS 1 投递;至少一次 |
| 资源占用 | broker 闲置 < 100MB RAM |
| 部署复杂度 | 单 `java -jar` 启动 broker,与 mica-admin 同进程或独立进程 |

## Phase 1 — IM 单聊 MVP

> **目标**:用户能与其他 mica-admin 用户发起 1-1 文本聊天。
> 这是 IM 的最小可用版本,验证"管理端 + App 端"打通。

### 用户故事

#### US-1-1 发起单聊

> **作为** 普通员工
> **我想要** 在通讯录中选择一位同事并发送消息
> **以便** 与同事即时沟通

**验收**:

- 通讯录用户详情页有"发消息"按钮
- 点击后跳到聊天页,可输入文字并发送
- 对方实时收到消息(< 2 秒)

#### US-1-2 接收单聊消息

> **作为** 普通员工
> **我想要** 在聊天列表看到新消息的红点
> **以便** 知道谁给我发了消息

**验收**:

- 收到消息后,会话列表项显示未读数红点
- 进入会话后,未读数清零
- 总未读数显示在底部 Tab 徽标

#### US-1-3 历史消息

> **作为** 普通员工
> **我想要** 查看与某同事的历史聊天记录
> **以便** 找回之前的对话内容

**验收**:

- 进入会话默认加载最近 20 条消息
- 上拉加载更多(分页)
- 历史消息按时间正序排列

#### US-1-4 离线消息

> **作为** 普通员工
> **我想要** 离线时收到的消息,上线后能看到
> **以便** 不漏掉重要消息

**验收**:

- 用户下线期间对方发的消息,存入 MySQL
- 上线后从 MySQL 拉取,按时间顺序展示
- 离线消息也计入未读

#### US-1-5 多端同步(基础)

> **作为** 普通员工
> **我想要** 在 Web 看到的消息,App 上也能看到
> **以便** 切换设备时对话连续

**验收**:

- Web 和 App 同时登录同一账号
- 任一端发送的消息,另一端在 2 秒内收到
- 会话列表在两端一致

#### 会话管理

| F1-1 | HTTP `GET /api/im/conversations` — 当前用户的会话列表 | P0 |

| F1-3 | HTTP `GET /api/im/conversations/p2p/{userId}` — 获取/创建与某用户的单聊会话 | P0 |
| F1-4 | HTTP `DELETE /api/im/conversations/{id}` — 删除会话(仅本地视角) | P0 |
| F1-5 | 会话自动创建:首次发消息时若会话不存在则创建 | P0 |
| F1-6 | 会话列表按最后消息时间倒序 | P0 |
| F1-7 | 显示对方用户信息(头像/昵称) | P0 |

#### 消息管理

| ID | 功能 | 优先级 |
|---|---|---|
| F1-8 | HTTP `GET /api/im/conversations/{id}/messages` — 拉取历史消息(分页) | P0 |
| F1-9 | MQTT `PUBLISH im/p2p/{fromId}/to/{toId}` — 发送单聊消息 | P0 |
| F1-10 | 消息持久化:broker listener 收到后写入 MySQL | P0 |
| F1-11 | 消息顺序:服务端写入时打 `client_msg_id`,客户端按该字段去重 | P0 |
| F1-12 | 消息状态:`sending` / `sent` / `delivered` / `read` / `failed` | P0 |
| F1-13 | 消息撤回:发送后 2 分钟内可撤回 | P1 |
| F1-14 | 消息类型:仅支持 `text`,Phase 1.1+ 增加 `image/file` | P0(text)/P2(others) |

#### 未读管理

| ID | 功能 | 优先级 |
|---|---|---|
| F1-15 | HTTP `GET /api/im/unread/count` — 当前用户总未读 | P0 |
| F1-16 | HTTP `PUT /api/im/conversations/{id}/read` — 标记会话已读 | P0 |
| F1-17 | 未读数实时更新:接收消息时 +1,标记已读时归零 | P0 |
| F1-18 | 会话列表显示各会话的未读数 | P0 |

#### 实时通道

| ID | 功能 | 优先级 |
|---|---|---|
| F1-19 | MQTT 订阅 `im/p2p/{myUserId}/from/{otherUserId}` — 接收单聊消息 | P0 |
| F1-20 | 消息体 JSON 格式:见 api-design.md | P0 |
| F1-21 | QoS 1 投递,确保消息到达 | P0 |
| F1-22 | 离线消息:用户上线时 HTTP 拉取 + MQTT 推送双保险 | P0 |

| ID | 功能 | 优先级 |
|---|---|---|
| F1-23 | 图片消息类型 | P2(Phase 2.0) |
| F1-24 | 文件消息类型 | P2(Phase 2.0) |
| F1-25 | 语音消息 | P2(Phase 2.0) |

### 非功能需求

| 类别 | 要求 |
|---|---|
| 消息延迟 | 局域网 < 500ms,公网 < 2s |
| 并发 | 100 用户在线 + 10 msg/s 总消息速率,稳定运行 |
| 可靠性 | 消息至少一次投递;MySQL 写入失败重试 3 次 |
| 顺序保证 | 同一会话内消息严格按时间顺序 |
| 离线消息 | 保留 7 天(可配置) |
| 安全 | 所有 MQTT topic 经 JWT 鉴权;用户只能订阅自己的 topic |
| 可扩展 | Phase 1.1 群聊可直接基于会话模型扩展 |
| 可观测 | 关键事件打日志:连接/断开/订阅/消息收发 |

## Phase 1.1 — 群聊

> **目标**:支持创建群、加入群、群成员管理、群消息收发。
> 部门群是 mica-admin 的天然优势(直接复用 sys_dept)。

### 用户故事

#### US-1.1-1 创建群

> **作为** 普通员工
> **我想要** 创建一个新群并邀请同事加入
> **以便** 多人协作讨论

**验收**:

- 选择联系人 → 创建群(填群名,可跳过)
- 创建者自动成为群主
- 群会话立即出现在会话列表

#### US-1.1-2 部门群(自动)

> **作为** 部门负责人
> **我想要** 系统自动为每个部门创建部门群
> **以便** 部门成员自动加入,无需手动拉人

**验收**:

- 创建部门时自动创建同名部门群
- 部门成员变更时自动同步增减群成员
- 部门群图标用部门图标

#### US-1.1-3 邀请/踢出成员

> **作为** 群主
> **我想要** 邀请新成员加入群,或踢出不当成员
> **以便** 维护群成员

**验收**:

- 群主/管理员可在群设置中添加/移除成员
- 被踢出成员立即从群中消失(会话保留或删除可选)
- 系统通知群成员"XX 加入/退出群"

#### US-1.1-4 群消息收发

> **作为** 群成员
> **我想要** 在群内发送消息,所有成员实时看到
> **以便** 多人讨论

**验收**:

- 群消息发布到 `im/group/{groupId}/inbox`
- 所有在线成员 < 2s 内收到
- 离线成员上线后能拉取离线消息

#### US-1.1-5 群信息查看

> **作为** 群成员
> **我想要** 查看群成员列表、群公告
> **以便** 了解群情况

**验收**:

- 群详情页显示群成员列表(头像/昵称/角色)
- 群主可编辑群公告
- 群主/管理员标有特殊标识

### 功能需求

#### 群管理

| ID | 功能 | 优先级 |
|---|---|---|
| F1.1-1 | HTTP `POST /api/im/groups` — 创建群 | P0 |
| F1.1-2 | HTTP `GET /api/im/groups/{id}` — 群详情 | P0 |
| F1.1-3 | HTTP `PUT /api/im/groups/{id}` — 修改群信息(仅 owner/admin) | P0 |
| F1.1-4 | HTTP `DELETE /api/im/groups/{id}` — 解散群(仅 owner) | P0 |
| F1.1-5 | HTTP `POST /api/im/groups/{id}/members` — 邀请成员 | P0 |
| F1.1-6 | HTTP `DELETE /api/im/groups/{id}/members/{userId}` — 踢出成员 | P0 |
| F1.1-7 | HTTP `GET /api/im/groups/{id}/members` — 成员列表 | P0 |
| F1.1-8 | HTTP `PUT /api/im/groups/{id}/members/{userId}` — 设置成员角色 | P0 |
| F1.1-9 | HTTP `POST /api/im/groups/{id}/quit` — 主动退群 | P0 |
| F1.1-10 | HTTP `GET /api/im/my/groups` — 我加入的群列表 | P0 |

#### 部门群(自动同步)

| ID | 功能 | 优先级 |
|---|---|---|
| F1.1-11 | 创建 `sys_dept` 时自动创建同名群 | P0 |

| F1.1-13 | 删除部门时群是否解散(可配置) | P1 |
| F1.1-14 | 部门群图标/名称继承部门 | P0 |

#### 群消息

| ID | 功能 | 优先级 |
|---|---|---|
| F1.1-15 | MQTT `PUBLISH im/group/{groupId}/inbox` — 发送群消息 | P0 |
| F1.1-16 | 群成员订阅 `im/group/{groupId}/inbox`(加入群时自动订阅) | P0 |
| F1.1-17 | 退群/被踢后取消订阅 | P0 |
| F1.1-18 | HTTP `GET /api/im/groups/{id}/messages` — 群历史消息 | P0 |
| F1.1-19 | 群消息体附加 `sender_id`、`sender_name` 字段 | P0 |

#### 实时通知

| ID | 功能 | 优先级 |
|---|---|---|
| F1.1-21 | 入群通知:`im/sys/{userId}/system` 推送"XX 邀请你加入群" | P1 |
| F1.1-22 | 退群通知:同上 | P1 |
| F1.1-23 | 解散群通知:全员推送 | P0 |

### 非功能需求

| 类别 | 要求 |
|---|---|
| 群规模 | 单群支持 200 人(Phase 1.1 不做大规模优化) |
| 群消息延迟 | < 1s(局域网) |
| 群消息顺序 | 严格按服务端写入顺序 |
| 部门群同步 | dept 变更 → 群成员同步延迟 < 30s |

## 不在范围内(明确不做)

### Phase 2.0+

| 功能 | 原因 |
|---|---|
| 已读回执 | 实现复杂,价值有限 |
| 撤回 | 价值有限,先不做 |
| @ 提及 / 引用回复 | 文本 + 简单功能为主 |
| 富文本消息 | 安全性考虑 |
| 表情 / 贴纸 | 暂不需要 |
| 消息搜索 | Phase 2.0+ 评估 |
| 文件/图片/语音 | Phase 2.0+ 评估 |
| 名片分享 | 可用"个人名片"代替 |
| 位置共享 | 不做 |
| 阅后即焚 | 不做 |

### 永远不做

| 功能 | 原因 |
|---|---|
| 音视频通话 | 自研成本高,集成第三方 |
| 智能助手 / Bot | 复杂度高 |
| 朋友圈 / 状态 | 偏离工具定位 |
| 直播 | 偏离工具定位 |
| 红包 / 支付 | 涉及金融合规 |
| 阅卷 / OA 表单 | 已有 sys_message 满足 |
| 商业化功能 | 开源定位 |

## 与 mica-admin 现有功能的对接

| mica-admin 现有能力 | IM 模块使用方式 |
|---|---|
| `sys_user` | 用户身份、昵称、头像 |
| `sys_dept` | 部门群自动创建、成员同步 |
| `sys_role` | 权限校验 |
| `sys_file` (x-file-storage) | Phase 2.0 文件消息存储 |
| `sys_message` | Phase 0 推送通道双向打通 |
| `sys_user_message` | 离线 IM 消息兜底 |
| `mica.security.jwt` | MQTT 鉴权 token 来源 |

> **不重复造用户/部门/权限/文件轮子**。

- [ ] 用户可在 Web/App 发起单聊,对方实时收到
