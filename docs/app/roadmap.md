# 迭代路线图

> App 的迭代节奏建议:**MVP(快速验证)→ 1.0(开箱即用)→ 1.1(增强)→ 2.0(深度集成)**。
> 每一阶段都基于 mica-admin 后端的真实能力,**不做超出后端能力的承诺**。

## 时间估算参考

| 阶段 | 工作量(单人) | 投入人员建议 |
|---|---|---|
| MVP | 1 周 | 1 前端 |
| 1.0 | 2-3 周 | 1 前端 + 0.5 后端(配合) |
| 1.1 | +2 周 | 1 前端 + 0.5 后端 |
| 2.0 | +4 周 | 2 前端 + 1 后端 |

> 工作量为**参考值**,实际依团队熟悉度、二次开发深度调整。

## MVP — 最小可演示版本

**目标**:用 1 周时间做出"能登录、能看消息、能看工作台"的最小版本,**快速验证方向**。

### 范围

只做 3 个核心页面:

1. **登录页**(复用 mica-admin-web `auth-mica-admin.ts`)
2. **工作台首页**(聚合调用)
3. **消息中心**

### 不做

- 应用中心(动态菜单)
- 我的(个人中心)
- 通讯录、通知、文件

### 后端依赖

**零后端改造**,全部用 mica-admin 现有接口:

```
/api/auth/public-key
/api/auth/captcha
/api/session
/api/auth/info
/api/system/user/message/unread
/api/system/user/message
/api/system/user/message/read/{id}
```

### 工作量

- 前端:1 周
- 后端:0
- 设计:1-2 天(MVP 阶段草图够用,不需要高保真)

### 验收

- [ ] 能登录、能退出
- [ ] 能看工作台(用户信息、未读数、最新公告)
- [ ] 能看消息列表、标记已读
- [ ] App 启动/退出流畅,无明显 bug
- [ ] 在真机(iOS/Android)和小程序端都跑得动

## v1.0 — 正式版本(11 模块)

**目标**:**App 端开箱即用**,完整覆盖 mica-admin 现有控制器中 App 适用的通用能力。

### 范围

11 个模块全部交付:

| # | 模块 | 后端接口 |
|---|---|---|
| 1 | 登录 | `/api/auth/*` + `/api/session` |
| 2 | 工作台 | 聚合系统未读 + 最新公告 |
| 3 | 消息中心(公告 + 系统消息) | `/api/system/user/message/*` + `/api/system/notice/feed` |
| 4 | 应用中心 | `/api/auth/menus`(WebView 兜底) |
| 5 | 我的 | `/api/system/users/*` |
| 6 | 通讯录 | `/api/system/users` + `/api/system/dept` |
| 7 | 通知公告 | `/api/system/notice/feed` |
| 8 | 文件中心 | `/api/upload/**` |

### 关键能力

- **完善的错误处理**(网络异常、401、500、业务错误码)
- **加载/空/错误三种状态**
- **国际化**(中/英)
- **基础性能优化**(图片懒加载、列表虚拟滚动、骨架屏)
- **权限适配**(菜单按 `isAdmin` 显隐)
- **App 自动更新**(可选,uniapp 自带)
- **基础埋点**(用户行为统计,可选)

### 工作量

- 前端:2-3 周
- 后端:0(零改造)
- 设计:1 周(高保真原型)
- 测试:1 周(多端兼容性测试)

### 验收

- [ ] 全部 11 个模块功能完整
- [ ] 公告 Feed 与系统消息双 Tab 切换正常
- [ ] 与 mica-admin 后端零改造对接
- [ ] 通过 App Store / 应用市场上架审核(若需要)
- [ ] 用户体验流畅,关键操作 < 3 步

### App 1.0 工程结构

```
src/
├── api/                       # 自动生成(从 swagger)
│   └── Api.ts                 # 系统模块客户端
├── modules/
│   ├── auth/                  # 登录
│   ├── workbench/             # 工作台
│   ├── message/               # 消息中心(公告 + 系统消息)
│   ├── menu/                  # 应用中心
│   ├── profile/               # 我的
│   ├── contacts/              # 通讯录
│   ├── notice/                # 通知公告
│   ├── file/                  # 文件中心
│   └── extension/             # ⭐ 二次开发预留
│       ├── README.md
│       ├── approval/          # 审批(等 sys_approval)— 二次开发
│       ├── attendance/        # 考勤(等 sys_attendance)— 二次开发
│       ├── im/                # 即时通讯(需自建)— 二次开发
│       └── placeholder/
├── pages.json                 # 路由
├── stores/                    # Pinia
├── utils/
│   ├── request.ts             # 网络请求(含 mica-admin code=0 适配)
│   ├── rsa.ts                 # RSA 加密(密码)
│   └── storage.ts             # 本地存储封装
├── components/                # 通用组件
├── locales/                   # i18n
└── config/
    └── env.ts
```

## v1.1 — 增强版本

**目标**:补齐 mica-admin 现有能力中 App 暂未覆盖的部分 + 轻量二次开发扩展。

### 范围

#### 1.1.1 mica-admin 现有能力补齐(0 后端)

- **我的 → 工作台快捷入口自定义**(本地持久化)
- **消息中心 → 已读/未读 Tab 切换**
- **通讯录 → 按部门/按职位分组**
- **通知公告 → 关键字搜索**

#### 1.1.2 二次开发扩展(选做)

按业务需求挑选,推荐组合:

| 扩展点 | 工作量 | 适用场景 |
|---|---|---|
| 消息跳转业务单据 | 1 天 | 几乎所有场景 |
| 数据看板(图表) | 1-2 天 | 管理员看数据 |
| 系统级推送(uniPush) | 0.5 天 + 1 天 | App 后台推送 |
| 工资条 / 通讯录增强 | 1 周 | 自定义业务 |
| 通讯录"打电话" | 0.5 天 | 原生拨号 |

#### 1.1.3 体验增强

- **离线缓存**(消息列表、通讯录)
- **App 启动图 + 引导页**
- **手势密码 / Face ID**
- **深色模式**
- **字体大小适配**

### 工作量

- 前端:2 周
- 后端:0-1 周(根据扩展点选择)

### 验收

- [ ] App 离线可用基础功能
- [ ] 至少完成 1-2 个二次开发扩展点
- [ ] 用户体验达国内一线 OA App 标准

## v2.0 — 深度集成版本

**目标**:把 mica-admin **从通用框架升级为完整业务平台**,App 端达到"企业微信 / 钉钉"轻量版能力。

### 范围

#### 2.0.1 审批中心(完整工作流)

接入轻量级工作流引擎(自研或 flowable lite):

- 请假 / 报销 / 出差 / 采购 / 加班 / 用车
- 多级审批、会签、或签
- 审批委托、撤回、转交
- 与消息中心深度整合(待办推送走系统消息)

#### 2.0.2 考勤打卡

- GPS / WiFi 打卡
- 排班 / 调班 / 请假联动
- 月历视图 + 异常提醒

#### 2.0.3 即时通讯(自建或对接第三方)

- 通用 IM 能力:单聊、群聊、会话列表
- 对接第三方(融云/环信/腾讯云 IM)或自研(基于 EMQX/Mosquitto 等)
- 与 mica-admin 解耦,**作为独立服务部署**,App 端只消费其 SDK

#### 2.0.4 音视频通话 + 系统级推送

- **音视频通话**:集成声网 Agora / 腾讯云 TRTC SDK
- **系统级推送**:uniPush / 个推(支持 iOS/Android/小程序)
  - App 后台推送通知
  - 推送模板 + 静默推送

#### 2.0.5 数据看板

- 多个图表(柱状、折线、饼图)
- 时间范围筛选
- 数据导出(Excel)

#### 2.0.6 知识库 / 公告评论

- 富文本编辑器
- 评论 + @提及
- 点赞 / 收藏

### 工作量

- 前端:4 周
- 后端:4 周(包含工作流引擎集成)
- 测试:2 周

### 验收

- [ ] 工作流可处理 5+ 种业务
- [ ] 音视频通话延迟 < 500ms
- [ ] 系统级推送 < 3s 触达
- [ ] 考勤数据准确
- [ ] 数据看板可配置

## v3.0 — 平台化(可选)

**目标**:App 端变成"App Store",支持插件式扩展。

### 范围

- **App 内插件机制**:每个二次开发方可以提供独立的 uniapp 页面包
- **后端 magic-api 深度集成**:App 端可视化配置工作流
- **低代码 App 构建**:业务人员可以拖拽配置 App 模块

> 这是远期愿景,不在当前路线图重点。

---

## 风险与决策点

| 风险 | 影响 | 缓解 |
|---|---|---|
| mica-admin 后端接口变更 | App 不可用 | api-mapping.md 同步维护 |
| uniapp 跨端兼容问题 | iOS/Android/小程序行为不一致 | 关键页面多端实测 |
| 工作流引擎选型 | 决定 v2.0 工期 | 1.1 阶段先做技术验证 |
| 二次开发方能力差异 | App 升级节奏不可控 | extension.md 提供模板 + 示例 |
